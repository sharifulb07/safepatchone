# SafePatch website, security, and release review — 2026-09-27

**Release decision: not ready for production promotion.**

This working-tree review fixes the public website and download journey and
strengthens release checks. It does not turn SDK implementations or command
shells into a complete hosted verification product. No deployment, release tag,
public artifact upload, customer mutation, or payment was performed.

### Paddle follow-up

The subsequent Paddle Billing integration adds server-created checkout, signed
subscription synchronization, and a portal link that requires Paddle billing-email
verification. See the [manual setup and acceptance guide](../architecture/paddle-setup.md).
The later browser suite has 14 passing tests. Migration 22 and real Paddle payments
still require infrastructure acceptance. The review archives documented below
predate this integration; rebuild releases from the updated source before using
Paddle. The local `bin/safepatch-api.exe` has been rebuilt for this integration.

## Scope and architecture

The repository map covers six command roles, shared application/domain services,
edition and feature configuration, authentication, authorization, licensing,
billing, storage, queues, scanner/language adapters, migrations, the Next.js site,
and the release pipeline. Existing source includes 539 tracked Go/TypeScript/SQL/
workflow files before the additions in this review. Repository-wide tests and
static checks supplement targeted code review; they are not a line-by-line audit
or proof that no security defects remain.

All five editions still use one codebase and one shared set of binaries. Plan
presentation is projected from the same Go catalog. Download eligibility uses
current organization membership, capabilities, independent permissions, and
artifact binding. Selecting an edition, changing a price label, or downloading
a binary grants no paid rights.

Local artifacts are in `dist/review-go1.26.8-20260927/`, with `checksums.txt`
and `release.json`. These are unsigned working-tree review builds, version
`0.2.0`, channel `nightly`. Their commit metadata identifies the base checkout;
it does not attest to the uncommitted changes included in these archives. They
have not been published. Native execution was checked only on Windows amd64;
the other target archives were inspected and checksum-verified locally.

Onboarding and signed-download browser responses use fixtures. Go tests exercise
the real guards and S3 signing implementation with test credentials, plus a real
local HTTP request during graceful shutdown. This is component and local browser
validation, not live GitHub/Stripe/S3/PostgreSQL production acceptance.

The initial Windows Go cache had a linker failure. A fresh cache under
`%TEMP%/safepatch-review-go-cache` resolved it. Web builds/browser tests required
execution outside the subprocess-restricted sandbox. Python's app launcher and
WSL were unavailable; no native PostgreSQL or Linux environment was established.

The remaining dependency-level advisory is
[GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932), covering the deprecated
`golang.org/x/crypto/openpgp` packages. They have no upstream fix and are not
imported or called by the scanned SafePatch code. The required crypto module is
retained for its other packages. This is recorded explicitly rather than hidden
or described as complete absence of dependency advisories.

## Remaining production blockers

1. **Executable product composition:** `internal/application/command.go` still
   reports `NOT_IMPLEMENTED` for verification. Worker, collector, replay, and
   MCP entrypoints remain shells. Hosted source fetching, concrete verifier and
   immutable-evidence execution, paid CLI identity/license composition, and
   completed proof delivery need implementation and live acceptance tests.
2. **Commercial configuration:** actual prices/currency/cadence, Stripe price
   IDs and account/webhook binding, sales contact, GitHub App credentials and
   callback domain, production session key, approved quotas, and private S3
   publication metadata must be supplied. Many catalog capabilities remain
   SDK/FUTURE; changing their labels would not implement them.
3. **Infrastructure:** execute all 21 migrations, concurrent tenant/quota tests,
   NATS delivery/recovery, S3 object-policy checks, GitHub OAuth, and Stripe
   lifecycle tests against provisioned test infrastructure. The CI database job
   is added but has not run in this local session.
4. **Native distribution:** cross-compilation is not native execution. Linux and
   macOS installers/runtime acceptance, Windows/macOS signing and notarization,
   provenance verification, and clean-machine installation remain release gates.
5. **Operations:** test graceful drain under traffic, backup/restore, secret/key
   rotation, monitoring, alert delivery, and outage recovery. The current API
   peer-IP limiter groups requests behind a proxy; use edge rate limits and
   validate intended multi-user capacity before production scaling.

These gaps are retained from the [earlier readiness review](v1.0-readiness.md)
where still confirmed by current source. This report supersedes its old checkout
location and test counts, but does not close untested infrastructure blockers.

## Reproduce locally

From the repository root, with the toolchain required by `go.mod`:

```powershell
$env:GOCACHE = Join-Path $env:TEMP 'safepatch-review-go-cache'
go test ./... -count=1
go test -race ./... -count=1
go test -race ./internal/platform/downloads -run TestEveryEditionProtectedDownloadBoundaries -count=100
go vet ./...
go mod verify
go run golang.org/x/vuln/cmd/govulncheck@v1.8.0 ./...
cd web
npm.cmd ci
npm.cmd run build
npm.cmd run typecheck
npm.cmd run test:e2e
```

Each command must succeed; a skipped native integration is not successful live
validation. On Linux/macOS use `npm` and install the Playwright Chromium browser.

## Configure the account website

1. Use `go build -o bin/ ./cmd/...` and build the web app from `web/`. The release
   packager builds all six roles for Windows/Linux/macOS, amd64 and arm64. Never
   use edition-specific builds.
2. Provision the database and apply the ordered migration history once. Follow
   [onboarding configuration](../architecture/onboarding.md) for required server
   variables and the GitHub callback. Use a random persistent 32-byte session key.
3. Configure Stripe offers and trusted provider account binding before enabling
   checkout. Set `SAFEPATCH_PUBLIC_PRICES` in the build environment only after
   approving corresponding amounts in the billing provider. Rebuild the site to
   publish changes. Missing prices remain clearly unpublished.
4. Upload verified immutable release bytes to a private object bucket and supply
   a catalog through `SAFEPATCH_DOWNLOADS_CONFIG`. Follow the
   [download guide](../architecture/download-distribution.md). No bucket or public
   download URL was fabricated by this review.
5. Start `bin/safepatch-api serve` (Windows: `bin/safepatch-api.exe serve`), set
   `SAFEPATCH_API_ORIGIN=http://127.0.0.1:8080`, and run `npm start` from `web/`.
   Use the same public HTTPS origin for the site and account API. The example
   `deploy/web.nginx.conf` includes ingress controls, fixed upstreams, webhook
   routing, and logs that omit sensitive query strings. Replace its domain and
   certificate paths. Never expose these loopback development listeners directly.
6. Probe `/healthz` and `/readyz` on the internal Go port, then exercise sign-up,
   sign-in, organization choice, checkout/trial confirmation, download eligibility,
   expired sessions, CSRF denial, permission revocation, and actual object delivery.

Account pages require the configured account service and HTTPS. The marketing
site can be previewed without it; account and download outages stay visible.
