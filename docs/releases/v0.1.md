# SafePatch v0.1 release preparation

Software version: **0.1.0**. Scope: **developer preview / shared Go foundation**.
Prepared on **2026-09-06**. This is a source-release preparation record, not an
announcement of publication or production readiness. No tag, signed distribution,
deployment, stable/LTS commitment or separate edition build is created here.

**Community, Developer, Team, Business and Enterprise all use this same release.**
There is one repository architecture, Go module, verification core, schema and
ordered migration history. The shared API-specification directory exists, but
the product API specification and endpoints are still unimplemented. No parallel
edition specification or migration stream is introduced.

The [v0.1 edition capability matrix](../editions/v0.1-feature-matrix.md) is the
release availability inventory. It identifies three implemented SDK capability
areas and marks the remaining 36 catalog keys **FUTURE**, never enabled product
workflows. Existing commercial seed grants do not prove implementation.

## What is included

- Offline Community CLI entitlement inspection: `entitlement show`,
  `entitlement explain <feature>`, `edition`, `whoami`, help and JSON error codes.
  It requires no account, subscription, Stripe or network service.
- Shared FeatureCatalog, all five edition identities, immutable bundle history,
  entitlement resolution/snapshots, independent actor authorization, and reusable
  API/CLI/worker admission helpers.
- Typed entitlement limits (`UNLIMITED`, `INTEGER`, `DISABLED`) and quota
  Check/Reserve/Commit/Release, with bounded memory and PostgreSQL accounting
  adapters. Missing policies fail closed; no plan-specific numeric defaults are
  invented by the release.
- Shared Verifier SDK, normalized evidence statuses, trusted LocalRunner and
  ContainerSandboxRunner. Sandbox configuration enforces non-root identity,
  disabled network, read-only root, bounded resources/output and cancellation.
- Go build, test, race, vet, Staticcheck, Govulncheck, fuzz and benchmark adapters;
  module, workspace and multi-module support.
- Configured Gitleaks, Semgrep, Trivy, OSV-Scanner and Syft adapters. Detection
  remains in the mature upstream engines. Exact captured scanner output is
  preserved separately from normalized reports in scoped immutable local storage.

These verification implementations are Go-callable components. **The CLI does
not yet run verification.** `safepatch verify` returns `NOT_IMPLEMENTED` and exits
1. The API, worker, collector, MCP-gateway and replay executables remain command
shells; they do not start functioning services.

## What is not included

Basic IntentGuard and local ChangeGraph remain FUTURE, as do advanced intent,
organization/cross-repository graphs, Proof Planner/Passport/Living Proof, replay,
shadow execution, invariants, incident antibodies, agent/MCP workflows, SSO,
enterprise audit, managed self-hosting and air-gap deployment. Business and
Enterprise receive no fictional implementation by virtue of their edition names.

Production authentication, tenant/persistence composition, hosted scanner jobs,
durable NATS consumers, cloud S3 storage, OpenTelemetry integration, product API
specification, dashboard and marketing application are not delivered by this
release. The local CLI is not a paid-account or licensing client. No payment,
subscription, license issuance, upgrade, installer or automatic migration workflow
is supplied.

## Version, edition and data compatibility

`0.1.0` identifies this source release; it is independent of edition bundle IDs
such as `community-2026-v2` and `team-2026-v1`. Existing catalog registration and
adapter version strings are not changed to match the product release. The current
command shells do not expose a product `--version` command or embedded release
attestation. Build provenance/signing remains required for a distributed binary.

No migration or entitlement allocation changes are made by this release task.
All editions share these four existing forward migrations, applied in order:

1. `000001_editions.up.sql`: permanent editions and immutable bundle schema.
2. `000002_initial_edition_bundles.up.sql`: initial commercial seed bundles.
3. `000003_entitlement_limits_quotas.up.sql`: limit policies and quota accounting.
4. `000004_community_local_bundle.up.sql`: local evidence identity and additive
   Community v2 bundle, preserving prior history.

See [migration instructions and native assertions](../../migrations/README.md).
Offline CLI inspection does not require PostgreSQL. Published migrations and
bundles must not be edited or reapplied. There are no down migrations or validated
production rollback/upgrade procedures. Edition changes must preserve historical
data and references; a grant downgrade is not a software/database rollback.

## Build and inspect from source

Use Go 1.26 or later. Dependency acquisition requires a prepared module cache or
network access at build time; the built entitlement-inspection CLI works offline.
Race testing on Windows additionally requires CGO and a compatible C compiler.

```powershell
go mod verify
go build ./cmd/...
go run ./cmd/safepatch --help
go run ./cmd/safepatch entitlement show --json
go run ./cmd/safepatch edition --json
go run ./cmd/safepatch whoami --json
```

Inspection reports the local Community bundle and an unauthenticated offline
session. It does not claim to be a logged-in member of another edition. The
following negative smoke checks are expected to exit nonzero:

```powershell
go run ./cmd/safepatch entitlement explain runtime.replay --json
go run ./cmd/safepatch verify --json
```

Their JSON error codes are `FEATURE_NOT_ENTITLED` and `NOT_IMPLEMENTED`,
respectively. When using `go run`, Go itself also reports the child exit status;
the built binary emits the single documented error envelope on stderr.

## Security and release boundaries

Only PASS represents a successful verification; UNKNOWN, UNAVAILABLE, SKIPPED,
WARN and errors never authorize production. Entitlements do not replace actor
authorization, quota admission or sandbox policy. LLM/scanner output cannot
directly authorize production.

LocalRunner is limited to explicitly trusted tools and sources. Untrusted local
or cloud source requires the container sandbox; a successful Windows unit test
does not prove live Linux isolation. Hosted workers must recheck access before
expensive work, using authoritative tenant grants rather than the offline provider.

Original evidence may contain credentials or private source. Keep its storage
outside source trees and scanner mounts, restrict access with OS ACLs, and enforce
authorization on retrieval. The local store does not add encryption at rest;
cloud encryption, storage lifecycle and operational controls remain future work.

This preparation adds release documentation and gives the real-disk scanner
integration fixture a ten-second persistence budget instead of one second, to
accommodate disk contention during release builds. Production limits and behavior
are unchanged; cancellation and archive-failure tests remain intact.
No publication or production sign-off
is implied by a passing source test suite. Before broader distribution, bind the
release to a source commit, produce verifiable build artifacts, and complete the
environment-dependent validation for the platforms and dependencies being claimed.
The checkout currently inherits the parent Documents Git root and is untracked;
this task does not initialize another repository, tag it or alter that Git boundary.
