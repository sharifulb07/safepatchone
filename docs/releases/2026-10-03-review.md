# SafePatch review - 2026-10-03

Production promotion remains blocked. The account website and existing shared
components have been hardened and validated locally; the verification product
still lacks executable worker and CLI composition. This review preserves the
substantial changes already present in the working tree. It does not publish a
release, deploy a service, process payments, or alter customer infrastructure.

## Changes in this review

| Finding | Fix and evidence |
| --- | --- |
| Next.js 16.3.4 is within the affected range of critical GHSA-vcvr-r3jv-pc5j. | Upgraded the exact dependency and lockfile to 16.3.8. The live npm registry audit reports zero vulnerabilities after installation. No `next/og` or `ImageResponse` usage was found in the application's page sources; a reachable exploit in SafePatch was not demonstrated. |
| Browser proxy silently drops Authorization and can execute a request using a different cookie identity. | Browser routes reject Authorization before forwarding. Browser tests send both credentials and require a 400 response with no caching. Direct Go bearer download access remains available. |

Duplicate sessions and empty cookie plus bearer requests cannot enter the download adapter. Tests cover both orderings and repeated identical values. |
| Maintenance can outlive API serving and touch a closed database/broker. | Deferred cleanup cancels and joins maintenance before closing dependencies, including listener startup failure. A regression blocks active work, verifies cancellation and proves cleanup waits for resource release. The existing real-HTTP in-flight shutdown test remains in place. |
| Setup documentation says the API cannot listen and the checkout shares its parent's Git root. | README now describes `safepatch-api serve`, the account website, existing infrastructure adapters, and the verified standalone Git root. |
| Local validation requires manually coordinating many commands. | Added `tools/verify.ps1`: module verification, tests, race tests, vet, vulnerability scan, all command builds, packaged CLI version, lockfile installation, live npm audit, production web build, TypeScript, browser tests and whitespace validation. `-Postgres` explicitly enables disposable live SQL acceptance. Failures stop execution and produce `dist/validation/report.json`; skipped SQL is recorded as `not_run`, and production readiness is always `not_certified`. |

The [Next.js advisory](https://github.com/advisories/GHSA-vcvr-r3jv-pc5j)
identifies attacker-controlled SVG inputs to Node.js ImageResponse as the affected
execution path. Updating removes the affected dependency without asserting that
this application exposed that path.

## Validation

The baseline full Go suite passed with Go 1.26.8. The original system Go cache
was inaccessible; checks use a fresh writable cache under the user's temporary
directory. Network scans, Next.js subprocesses and browser execution require
permission outside this session's sandbox.

The official `govulncheck@v1.8.0 ./...` scan reported zero reachable vulnerabilities,
zero vulnerabilities in imported packages and one advisory in required modules
whose affected code is unused. This remains a qualified scan result, not a claim
that every dependency is free of advisories.

The production Next.js 16.3.8 build, standalone TypeScript checks, all 15 production
Playwright tests, full Go race suite, Go vet, module integrity and builds of all
six commands passed. The browser suite covers page navigation, responsive layouts,
nonce CSP hydration, onboarding, Paddle checkout fixtures, signed download guards,
outages and the new credential-conflict regression. Infrastructure responses in
these browser tests are fixtures, not live external-service acceptance.

All six rebuilt Windows commands passed `version --json`; local CLI entitlement
inspection passed. `bin/safepatch.exe verify --json` returned the expected
`NOT_IMPLEMENTED` envelope with exit code 1, confirming the executable production
blocker. These local builds report `dev`/unknown commit metadata and are unsigned
development artifacts, not release packages. Final targeted race regressions and
`git diff --check` also passed.

The validation script passed PowerShell parsing and an isolated failure harness
that checks nonzero tool status, JSON failure reporting and restoration of working
directory/environment. The complete script has not been executed as one command;
its substantive checks are run individually in this review. Browser installation
is an operator prerequisite (Chromium through Playwright, or the configured Windows
Edge executable).

## Run the checks

From the repository root on Windows:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/verify.ps1
```

For live SQL acceptance, provision a **disposable test database**, configure the
standard libpq `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD` and
`PGSSLMODE` settings, install `psql`, and run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/verify.ps1 -Postgres
```

The execution-policy flag applies only to the new PowerShell process; it permits
this locally reviewed unsigned script without changing the machine policy.
The script runs `npm ci`, which replaces installed web dependencies according to
the project lockfile. It rebuilds all six local command artifacts. Its output
report is ignored through the existing `/dist/` rule. Credentials are not included
in the report. A successful local report does not certify production readiness.

## Unresolved production requirements

1. `safepatch verify` still returns `NOT_IMPLEMENTED`. Worker, collector, replay
   and MCP command entrypoints remain shells. Source acquisition, tenant/permission/
   entitlement/quota admission, immutable revision verification, evidence
   persistence and completed first-proof delivery need trusted runtime composition.
   SDK implementations and queued proof jobs do not satisfy this requirement.
2. Live PostgreSQL acceptance of all **22** migrations remains unverified locally.
   No `psql` or Docker executable is available in this environment. Passing ordinary
   Go tests includes explicitly skipped SQL integrations. CI's disposable database
   job must pass and storage adapter behavior must be tested against real SQL.
3. NATS durable delivery/recovery, private S3 object delivery, GitHub OAuth/App
   installation and Stripe/Paddle subscription lifecycle need provisioned test
   infrastructure and credentials. Browser fixtures do not certify these services.
4. Production HTTPS domain, persistent session key, provider account binding,
   approved offers/prices, private artifact publication, backup/restore, monitoring,
   key rotation and incident recovery must be configured and exercised.
5. Linux/macOS native acceptance, signed/notarized distribution and published
   provenance remain release gates. This run builds and executes Windows artifacts
   only. Prior review ZIPs predate these changes and must not be promoted as current.
