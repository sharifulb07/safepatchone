## Evidence levels

- **PASS (component):** executed code/test assertions, possibly using fake SQL,
  HTTP, clock, sandbox or storage dependencies. This is not a deployed journey.
- **PASS (native):** actual local binaries/tooling executed successfully.
- **FAIL:** an executed assertion or required operation failed.
- **BLOCKED / NOT VERIFIED:** missing implementation, infrastructure or evidence.
  A skip, UNKNOWN result or missing dependency is never PASS.

## Release hold and acceptance procedure

Do not create a production version tag, publish images/assets, promote channels or
publish a release while any blocker is open. This document records a **review
hold**, not a newly implemented CI enforcement mechanism. The existing workflow
can push images on a tag before draft creation and does not parse this review;
passing its current tests alone is insufficient release authorization. Configure
and verify release-environment protection and required readiness checks before
any publishing run (B09).

Close blockers against a tracked candidate with owners and evidence links. Build
the six roles once per supported platform; record artifact digests; reuse those
bytes across all edition scenarios. Independently vary grants, actor permissions,
limits and current subscription/license state, retaining the same data through
downgrade/expiry/restore. Rerun the complete Go/race suites, frontend checks and
native infrastructure/security/recovery matrix. Only after every blocker has
accepted closure evidence should a release approver consider promotion.

go test ./internal/replay -run '^$' -fuzz FuzzDataset -fuzztime 5s -parallel 2

Inspect each command's exit status; this is an investigative sequence, not a
fail-fast release script. Enable the migration opt-in only against an explicitly
configured disposable PostgreSQL instance, following [migrations](../../migrations/README.md).
The test creates and drops its own schema; never point it at production.
Run `npm.cmd run build`, `npm.cmd run typecheck` and `npm.cmd run test:e2e` from
`web`; the browser suite starts its own local server.

Session-local raw results are in the `%TEMP%` JSONL files above,
`safepatch-v1-readiness-native-go.txt`, and
