# Signed organization licenses

`internal/licensing.EnterpriseLicenseEntitlementProvider` implements the existing
`entitlement.EntitlementService`. Self-hosted composition can inject it into the
same admission guards as other providers. It translates verified licenses into
canonical `ENTERPRISE_LICENSE` records and uses the shared EntitlementResolver;
there is no alternate verifier, permission system, edition fork or release stream.

The node verifies [standard Ed25519 signatures using Go's crypto/ed25519](https://pkg.go.dev/crypto/ed25519).
Its configuration accepts only a bounded map of issuer key IDs to 32-byte public
keys. It clones those bytes. There is no license-signing operation, private key
configuration, key-generation operation or embedded private license key in node
code. Private keys generated by tests are ephemeral test-only signing fixtures.
An architecture test rejects signing APIs in non-test licensing source.

## Document and signature format

The single OpenAPI specification defines `SignedEnterpriseLicense` and
`EnterpriseLicenseDocument`. The envelope contains schema, algorithm, key ID,
document and a standard padded base64 signature. The signed document contains:

- license ID and organization ID;
- edition and immutable edition version ID;
- explicit feature grants, each with stable key, enabled flag and nullable
  per-feature limit;
- explicit resource limits using the shared INTEGER, UNLIMITED and DISABLED model;
- whole-second RFC3339 `issued_at` and `expires_at` timestamps.

The edition/version pair must exist in the trusted catalog. Edition labels do not
grant capabilities: only the signed feature entries do. Custom signed contracts
can select features without replacing historical edition bundles. The format
accepts the existing five editions and never compares an organization's edition
to decide operation behavior. Product version and release channel are separate.

`SigningBytes(keyID, documentJSON)` defines the public interoperability contract.
The issuer signs its returned bytes with Ed25519 outside the self-hosted node:

```text
safepatch.signed-license.v1\n
Ed25519\n
<key_id>\n
<canonical document JSON>
```

Here `\n` denotes one actual newline; there is no added newline after the JSON.
Canonicalization rejects duplicate keys, unknown fields, case aliases and ambiguous
typed values, preserves numeric precision with `json.Number`, and serializes
object keys deterministically with Go JSON encoding. Array order remains signed.
Issuers should call the helper or implement exactly this documented encoding;
this format does not claim generic RFC 8785 compatibility. Structural/time/catalog
validation is repeated by the verifier after signature verification.

All grants, limits, timestamps and organization identity are inside the signature.
The key ID and algorithm are also bound by the signing message. Unknown key IDs,
algorithm substitutions and signatures of the wrong size fail closed. License
documents cannot provide public keys, key-discovery URLs or executable extensions.
Verification performs no network lookup. Document plus envelope are limited to
256 KiB, the key ring to 32 entries, grants to 512 and resource keys to the shared
catalog's ten current keys. Duplicate features/resources are rejected.

## Runtime resolution and lifecycle

`ProviderConfig` requires the configured organization, trusted public keys, feature
and edition catalogs, a LicenseSource and a clock. It does not infer tenancy from
the license and rejects requests for any other organization before loading data.

The source returns one owned snapshot containing the signed envelope, a nonzero
monotonically increasing installation revision and revocation state. Installation,
replacement, removal and revocation must atomically advance that revision. The
source is an operator-owned infrastructure boundary; an uploaded JSON object must
not be allowed to self-declare installation or revocation authority.

Connected and air-gapped deployment policies now build on this verifier. See
[license connectivity](license-connectivity.md) for the optional background
refresh worker, persistent confirmation anchor and bounded outage grace.

Every Has, Resolve, feature Limit, Inspect and ResourceLimit call reloads source
state, verifies the signature and validates the clock and expiry. There is no
positive entitlement cache and no fallback to Community, Stripe, an edition's
default features or stale grants when verification fails. A missing feature is
denied. A missing resource limit is DISABLED; a null feature limit remains
unspecified and produces the existing Limit error.

The provider tracks the highest observed source revision and wall clock in memory.
Revision rollback, content changes at the same revision and clock rollback are
rejected. These checks serialize concurrent reads, but are not durable anti-rollback
protection across process restarts. Durable monotonic installation state and a
trustworthy clock are deployment requirements. An offline node cannot discover
remote revocation until authoritative state is delivered; revocation delivery and
public-key rotation belong to the operator/control plane. Rotate trusted keys by
recomposing the provider with the approved public-key set. Never accept a key from
the license being verified.

Inspect returns an immutable verified document snapshot suitable for reporting;
it does not confer continuing access after expiry. Do not retain it as a runtime
entitlement cache. This provider is a dedicated installed-license authority. A
deployment requiring merged subscription/default/manual sources must use the
existing atomic SnapshotSource/revision contract rather than concatenate stale
provider reads.

## Quotas and independent authorization

`LicensedQuotaStore` wraps the existing QuotaStore. It obtains current signed
resource limits when admission asks `QuotaTransaction.Limit`, while delegating
usage, reservation identities and settlement to the existing ledger. In this
dedicated license configuration, stored database limit rows do not supply grants;
the signed limits are authoritative. This wrapper does not implement a merge of
manual restrictions with signed resource grants.

Renewal, edition metadata changes and reduced limits do not delete usage or
reservations. Existing usage above a reduced ceiling blocks new consumption.
Expiration/revocation prevents new admitted work, but does not prevent release
or settlement of existing reservations. Shared idempotent reservation retries
retain their original responses; they are not permission to dispatch again.

Quota ownership never replaces actor authorization. Continue to use the shared
ExecutionGuard and independent PermissionService, including before queued work
executes. Self-hosted startup and dispatch must require the
`enterprise.self_hosted` capability through the same entitlement service; do not
infer it from `edition: enterprise`. The provider neither authorizes production
nor disables VerificationIntegrity, PolicyGuard or SelfApprovalGuard.

## Scope and validation

The base signed-license milestone supplied the public-key verifier, provider and
ledger adapter without a migration. The subsequent connectivity milestone adds
the optional refresh transport and PostgreSQL installation store in migration
000015; its deployment contract and remaining integration boundaries are in
[license connectivity](license-connectivity.md). No private-key-bearing issuer
or public license upload endpoint is shipped. Existing edition bundles remain
immutable.

Tests cover valid signed grants and limits, absent grants, signature forgery,
wrong organization/key/algorithm, unknown and duplicate fields, malformed limits,
edition-version mismatch, future/expired/revoked licenses, source errors, stale
revisions, clock rollback, concurrent verification, independent user permissions,
renewal/downgrade history and settlement after expiry. An architecture check keeps
license-signing APIs outside node code. Decoder fuzzing uses a valid signed seed
and malformed JSON.

```powershell
$env:GOCACHE = Join-Path $env:TEMP 'safepatch-go-build'
$env:GO_TELEMETRY_CHILD = '2'
go test ./...
go test -race ./...
go vet ./...
go test ./internal/licensing -run '^$' -fuzz FuzzLicenseEnvelope -fuzztime 5s -parallel 2
```

Base signed-license milestone validation on 2026-09-07: `go test ./...`, `go test -race ./...` and
`go vet ./...` passed on the final implementation. The decoder fuzz smoke test
passed with 79 executions. Existing migration contract tests passed; native
PostgreSQL execution remained skipped because the opt-in database/libpq test
environment was not configured. That base milestone changed no database schema.
